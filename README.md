## 目的

民間の修繕・改修を初期対象に、ConoHa VPSで運用する製品を開発しています。
旧版の画面検証・端末保存実装を保持しながら、認証・共有保存・権限を備えた製品用実装へ段階的に移行します。

## 製品用基盤（2026-10-26）

- `product.html`: DBセッションによるログイン、自社工事の登録・参照・更新、変更履歴。
- PostgreSQLによる会社分離、管理者・担当者・閲覧者の権限、同時更新検知、登録の二重送信防止。
- 工事変更のDBトリガーで監査記録を必須化し、同じトランザクションで確定。DB実行ロールは履歴の直接挿入・更新・削除不可。過去の履歴も順に取得できます。
- 工事詳細の「契約前の確認」で、工事条件・施工範囲・金額と許可・関連条件を4段階で途中保存。不明を適合扱いせず、確認課題と出典を表示します。
- 工事登録後の次作業ボタン、保存して次へ進む操作、保存後の残件から入力欄へ戻る導線を提供。未回答を選ばせる操作を省き、金額・工事候補を直接入力できます。支給材・分割契約・下請発注がない場合は関連欄を省略し、既存回答を保持します。
- 分類には独立した版・変更履歴があり、工事情報の変更後は前提の違いを表示します。保存結果不明や同時更新では入力を保持し、保存内容との比較を求めます。
- 「工事を進める」から、資料確認記録、見積・契約書案・変更、工程・撮影、写真台帳・掲示物、請求・入出金を扱えます。書類と記録はPostgreSQL、写真・証拠は認証付きの非公開保管先へ保存します。
- 写真はその場で撮影・送信。通信が切れた場合は利用者・会社・工事に固定した送信待ちを端末へ保管し、再送します。端末保管とサーバー保存を区別します。
- 発行済み書類の変更・削除、事実記録の書換えをDBで拒否し、業務記録の版と監査履歴を保持します。金額は整数演算で扱い、税額を帳票単位で丸めます。
- 分類は申告、資料確認は担当者の記録です。証拠の自動審査、本人・署名権限の証明、自動契約成立、着工許可は提供しません。契約書案と実際の交付・承諾記録を区別します。
- 公開サインアップ・画面でのロール切替は提供しません。開発アカウントはローカルだけで発行。
- GitHubはコードの保存先です。工事データの共有DB・バックアップ・写真の保管先ではありません。
- 旧版 `index.html` のIndexedDBは読み取り・送信・移行しません。API失敗時に端末保存へ切り替える動作もありません。

## 打ち合わせ反映版（2026-10）

- メインメニューを「ホーム・工事・書類」に集約。工事内で4段階の作業を案内し、過去の段階や従来の画面にも戻れます。
- 各工事の作業名・担当業者・日時・状態を編集する工程表。作業一覧と週表示、PDF出力に対応。
- 工事内からカメラを起動し、施工前・作業中・完成の区分と工事情報を自動で付けて保存。連続撮影、説明の編集、元写真のダウンロードに対応。
- 写真はIndexedDBの書込み完了後にのみ保存済み表示。容量不足時は未保存写真を保持し、再試行・退避・明示的な破棄を選択できます。
- 表紙・工事概要と1ページ3枚の写真台帳をPDF化。写真の縦横比を維持し、原本画像には加筆しません。施工前・完成写真の不足時は作成中と表示。
- 工事・日程変更・延期・中止・完了のお知らせ。騒音、断水、停電、通行制限等を選択し、文面・日程・施工会社からA4 PDFを作成。未記入ひな形は共通の書類画面から取得できます。
- 見積・注文・請書・請求の簡易PDF。明細と工事情報を共通化し、発行したPDFは発行時点の内容で保存します。
- 新規工事、基本情報、工程、写真、発行書類はブラウザを再読込しても残ります。添付された実案件の写真・個人情報・印影は収録していません。

### 保存・運用上の制約

この版は端末内保存の動作確認用です。写真・書類は当該ブラウザのIndexedDBに置き、サーバーには送信しません。端末・ブラウザ・配信元URLが異なると同じ記録は見えません。ブラウザデータの削除、プライベートモードの終了、端末故障、ブラウザによる保存領域の消去で失われる可能性があります。バックアップは自動化していません。実案件の唯一の保管先にはしないでください。

カメラ利用にはHTTPS（開発時はlocalhost）と利用者のカメラ許可が必要です。直接起動できない場合は端末カメラの撮影結果を即時保存します。この経路では撮影時刻を推定せず、登録時刻と区別します。画面のオフライン再起動、端末間共有、利用者認証、サーバー保管は未実装です。実機のiPhone/Androidでの確認は別途必要です。

生成帳票はモック用の簡易様式です。契約・発注者の指定様式、公共工事の写真管理基準、電子納品要領、適格請求書の要件への適合は保証しません。提出物は発行前に確認する前提です。専用機器を必要とする機能、CCUS等の外部業務連携は追加していません。

PDFはCanvasの日本語描画を画像化して埋め込んでいるため、文字検索・テキスト選択・アクセシブルPDFには対応しません。`public/vendor/` にpdf-lib 1.17.1の公式UMD配布物とMITライセンスを同梱しています。

### ブラウザ検証

`npm run build` 後、Playwrightを利用できる環境で以下を実行します。

```bash
node tests/field-smoke.mjs --browser /absolute/path/to/chrome --out test-results
```

Playwrightが別の場所にある場合は `--playwright /absolute/path/to/playwright` を指定します。テストはビルド済みファイルをブラウザのリクエスト介入で配信し、模擬カメラで撮影、保存失敗と再試行、再読込、工事別の分離、工程・帳票、360/390/768/1440pxの表示を確認します。制限環境ではOS側のダウンロードがキャンセルされるため、PDFは実際のBlobとダウンロード用リンクを境界で検査し、検査用ファイルを出力します。実機撮影や実回線での配信確認を代替するものではありません。

## 法令確認の試作（2026-10-22）

工事内の「工事の確認」に条件の段階入力と根拠資料付き記録を追加。未記録・未解決・条件変更時は次の段階への変更を停止します。記録ありは適法性の認定ではありません。

調査根拠、未対応事項、本番までの条件は [法令対応レビュー](docs/compliance-review-2026-10-22.md) を参照してください。認証・サーバー保管・資料内容の審査・行政提出は未実装です。

工事内の「検査・下請支払」に取引ごとの基準日、分割支払、入金対応額、実行済み支払、根拠資料・訂正履歴を追加。契約期日と建設業法の一部期限を比較し、完了工事を含めてホームに要対応を表示します。請求書未着を理由に期限を繰り延べません。不明な条件・特約は要確認とし、外部入出金・フリーランス法・利息等は自動判定しません。

ルール試験（Node.js 24）：`node --test tests/compliance.test.mjs tests/payment.test.mjs`

実ブラウザ試験：`tests/payment-smoke.mjs`。起動済みの開発サーバーに対し、`--playwright`（Playwrightの絶対パス）、`--browser`（Chromeの絶対パス）、`--out`（試験結果フォルダ）を指定します。独立したブラウザコンテキストで試験するため、利用者の保存データは変更しません。
