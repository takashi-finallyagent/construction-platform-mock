# 建設業務サービス 法令対応レビュー・実装範囲

資料確認日：2026-10-22 / 試作ルール：2026-10-22.1

## 結論

現状は業務モックであり、コンプライアンスを担保するサービスとして本番利用できる状態ではない。
今回追加したのは「適用条件を集め、担当者の根拠付き確認記録が不足する場合に段階変更を止める」試作と、取引別の検査・下請支払期限の管理。
資料内容の適否、本人性、現場の実態、実際の入出金までは検証しない。入力された基準日・金額による期限比較に限り、記録ありを適法・承認済みとは表示しない。

全国・全工種・全取引に適用する法令を一度の調査で網羅したという結論ではない。所在地、工種、規模、取引関係、作業者属性、契約日等を確定し、専門家による適用確認と法改正管理を継続する必要がある。

外部連携を実装しないことと、法令上の申請・報告をしないことは別。対象手続は外部で実施し、控えを管理する。現場掲示・保護具・有資格者による調査などもスマホで代替できるとは限らない。サービスが専用ハードを要求しない方針でも法定措置は省けない。

## 役割と画面

現場担当者に法律の分類・解釈をさせない。現場は工事を選び、写真・出来事・作業実績を残す。事務担当者が会社情報・契約・届出を揃え、権限を持つ責任者が根拠を確認する。

メインメニューはホーム・工事・書類の3つを維持する。「工事の確認」を工事内に置き、今の段階で必要なものを1件ずつ表示。全項目・履歴は折りたたんで後から参照できる。

目標の業務状態：

```text
工事条件の収集
  -> 適用判定（不明は未解決）
  -> 必要な証拠の取得
  -> 責任者の審査・承認
  -> 契約／着工／変更工事／引渡し
  -> 期限内の支払・保存
条件変更・資料失効・法改正 -> 影響範囲を再審査
```

試作では責任者認証・審査・サーバーでの常時監視は未実装。全記録を担当者の自己申告として扱う。端末で画面を開いている間は入力済みの期限を比較し、ホームに期限超過・7日以内の支払等を表示する。

### 数値条件の混同を防ぐ

許可の軽微工事の金額基準は原則税込。建築一式以外500万円未満、建築一式1,500万円未満などの基準があり、建築一式には一定の木造住宅の面積による例外もある。「一式」という見積表記だけで建築一式工事には分類しない。特定建設業許可は直接元請の下請契約総額5,000万円以上、建築工事業8,000万円以上を確認する。[国交省・許可の説明](https://www.mlit.go.jp/totikensangyo/const/1_6_bt_000080.html)

軽微工事判定の支給材料・運送費と、特定許可判定の下請合計では集計範囲が違う。分割契約の合理的理由や材料の評価も担当者が確認する。今回の数値表示は注意喚起であり、木造例外・業種認定・許可の有効性を自動認定しない。[近畿地方整備局・建設業法資料](https://www.kkr.mlit.go.jp/kensei/qgl8vl0000006rw5-att/all-data_R0704.pdf)、[関東地方整備局・一般／特定の集計説明（旧金額のため現行閾値には使用しない）](https://www.ktr.mlit.go.jp/ktr_content/content/000862452.pdf)

専任は単に請負額だけで全件判定するものではない。公共性、工事種類、兼任特例、雇用関係等の条件がある。小額だから主任技術者も不要と扱わない。[監理技術者制度運用マニュアル](https://www.mlit.go.jp/totikensangyo/const/content/001859191.pdf)、[2026年1月改訂の施工体制資料](https://www.kkr.mlit.go.jp/kensei/kensetsu/tekisei.html)

### 契約・期限の確認内容

第19条の必要事項は工事内容・金額・着手完成時期だけではない。非施工日等、前払等、変更・中止、不可抗力、価格変動、第三者損害、支給貸与、検査引渡し、完成後支払、契約不適合等、債務不履行、紛争解決も、各号の条件を踏まえて確認する。注文書・請書の単体発行では足りない。[ガイドライン第12版 第2章](https://www.mlit.go.jp/totikensangyo/const/content/001979927.pdf)

電子契約には事前承諾や技術的要件等があり、アプリ内の確認チェックやPDF保存と同一視しない。[2025年9月の電子契約ガイドライン](https://www.mlit.go.jp/totikensangyo/const/content/001912595.pdf)

見積期間は予定価格の区分に応じ原則1日・10日・15日以上。起算の扱い、短縮できる例外、入札の扱いを含めて仕様化する。労務費の適正性は単一の固定料率だけでは判定できない。[ガイドライン第12版 第1章](https://www.mlit.go.jp/totikensangyo/const/content/001979927.pdf)

下請工事の検査は完成通知を受けて20日以内かつ可能な限り短期間。支払は、出来高等の受領後1月以内の規定、特定建設業者に対する引渡申出から50日以内の規定等の適用条件を分ける。後者には下請の特定許可・資本金による除外がある。請求書未着を理由に法定期限を後ろへ動かさない。[国交省・検査引渡し](https://www.kkr.mlit.go.jp/kensei/sitauke/pdf/shitauke3103.pdf)、[ガイドライン第12版 第10章](https://www.mlit.go.jp/totikensangyo/const/content/001979927.pdf)

保存は一律5年でも一律10年でもない。帳簿と添付書類、住宅新築、営業に関する図書、作成された見積・相互交付された打合せ記録等の種類、対象者、起算点を管理する。2025年改正後の見積等の保存対象も落とさない。[ガイドライン第12版 第13章](https://www.mlit.go.jp/totikensangyo/const/content/001979927.pdf)

## 検査・下請支払の追加実装

工事内の `/sites/:siteId/payments` に、自社から下請への建設工事の発注契約を登録する。メインメニューは増やしていない。取引登録は「相手と金額」「支払の約束」「記録」の3段階。完成通知・検査・引渡申出・出来高等の入金・支払は、その都度1件ずつ記録する。

### 根拠と日付計算

- [東北地方整備局・2026年3月ハンドブック45〜48頁](https://www.thr.mlit.go.jp/bumon/b06111/kenseibup/kensetsu_shido/kensetsu_shido_files/handbook_point.pdf)：一般／特定の対象と50日ルールの除外、1か月は初日不算入、50日は申出日を含むという説明を確認。許可なしの支払側に同じ法定義務を自動適用しない。不明な許可条件では仮の警告を残す。
- [e-Gov・建設業法24条の6第2項](https://laws.e-gov.go.jp/law/324AC0000000100)：今回取得できた該当条項の検索本文で、対象契約に支払期日がない場合は申出日をみなし期日とすることを確認。空欄を一律に50日後へ変換しない。未確認と、合意していないことが判明した場合は別の状態。
- [参議院法制局・民法138〜143条の期間計算の説明](https://houseikyoku.sangiin.go.jp/column/column011.htm)：暦月は翌日の応当日前日、応当日がなければ該当月末。単純な30日加算ではない。例：2026-01-30入金は2026-02-28、2026-02-28入金は2026-03-31。月末・うるう年の単体試験を追加。
- 検査は通知日を除いて20日、50日ルールは申出日を含むため49日加算。1か月・50日はそれぞれ独立した義務であり、契約による早い期日も後ろへ動かさない。請求書の受領を計算開始条件にしない。

休日延長の成立条件、24条の4第2項ただし書の引渡特約の有効性は自動審査しない。特約あり・不明は申出日からの仮警告と要確認を表示し、期限を自動延長しない。表示の「管理期限超過」はこの保守的な警告日との比較であり、法令違反の確定表示ではない。検査前の申出も消さず、前提未確認の仮警告にする。

### 金額・履歴

- 1取引は1つの下請契約。契約の分割支払予定額の合計を税込契約総額に一致させる。
- 上位業者からの入金は、その下請の出来形に相応する支払対象額を手入力する。上位業者からの入金総額・他の下請の金額を混ぜない。配分の適否は自動認定しない。
- それぞれの期限までに必要な支払累計と、実行済み支払累計を比較。契約・1か月・50日の額を足して二重計上しない。現時点の不足額と、期限時点の不足額を分ける。支払後も遅延履歴を残す。
- 支払実績には資料添付を必須にするが、資料内容・振込実行の真正性は未審査。予約・手形・相殺を振込や現金の実績に混ぜない。
- 誤入力の訂正は理由付きの追記。旧実績・添付は削除せず、訂正対象を現在の計算から除外する。条件訂正も旧版を保存する。実際の返金・組戻しの会計処理は未対応であり、誤記訂正で代用しない。
- 条件訂正後の計算は最新版に基づく。変更契約の効力発生日別の債務再構成、旧条件による遅延額の自動再現、改変防止・署名付き監査証跡は未対応。古い条件は履歴から個別照合する。
- 完了・請求段階の工事もホームの期限警告から除外しない。画面を閉じた間の通知は未実装。端末日付への依存も本番ではサーバー基準へ変更する。

前払金、利息、控除、フリーランス法等は別途確認が必要。フリーランス法は個人だけに限定されず、60日・再委託・休日等の条件を今回の建設業法の計算に混ぜていない。[公取委のQ&A](https://www.jftc.go.jp/fllaw_limited/fllaw_qa.html)

## 関連法令の確認対象

以下は適用判断が必要な対象一覧。すべてを全工事に義務付ける一覧ではない。具体的な工事内容・対象者・自治体等が不明な部分は未判定。

| 領域 | 必要となる場面・確認事項 | 試作の状態／担当 |
| --- | --- | --- |
| 労災・雇用・社会保険 | 現場の労災と会社の雇用保険を分離。元請・下請・一人親方等の対象関係を確認 | 根拠資料確認のみ。既存料率画面・チェック欄は申告証明にならない。事務・社労士等が確認 |
| 労働基準法 | 労働者ごとの全現場横断の時間、休憩休日、36協定、賃金等 | 工程表だけでは勤怠・上限規制を検証できない。雇用主が管理 |
| 労働安全衛生法 | 高所・足場・電気・重機・化学物質等、資格／教育、計画・点検、元方調整、熱中症等 | 作業別チェックは未実装。安全担当の適用確認表を要求 |
| 石綿則・大気汚染防止法 | 既存建物等の解体改修。事前調査、資格、報告、掲示、必要な届出・防止措置 | 少額でも確認対象。新築のみ等と確定しない限り確認項目を表示 |
| 廃棄物処理法・建設リサイクル法 | 廃材処理、許可業者への委託、マニフェスト、特定建設資材等 | 根拠記録のみ。電子マニフェスト登録等は外部で実施 |
| 建築基準法・建築士法等 | 新築・増改築・一定の大規模修繕、設計監理、用途・構造等 | 適用判定未実装。建築士・確認機関と判断。確認対象外と性能基準適合は別問題 |
| 地域・専門工事 | 道路使用／占用、騒音振動、消防、電気・給排水・ガス、解体業登録、建設発生土・盛土、冷媒等 | 全国共通の数値で免除にしない。工種と住所から対象行政庁・資格・届出を追加調査する必要あり |
| 取引相手と契約類型 | 一人親方等への委託、建設以外の製造・運送等、消費者との取引、住宅新築 | フリーランス法、取適法等の適用を契約実態から確認。建設業だから全取引が同一法の対象とはしない。詳細判定未実装 |
| 電子帳簿保存・税務 | 電子授受した見積／契約／請求等、適格請求書、紙の課税文書等 | PDFダウンロードだけでは保存要件・税務要件を検証できない。税務担当が設計確認 |
| 個人情報・サービス運営 | 作業員の身分・健康・資格、住民情報、写真、会社間共有 | 認証、会社間分離、権限、委託先管理、保存削除、漏えい対応は未実装。試作には実際の機微情報を投入しない |

## 改正・施行日の管理

法令・通達・行政ガイドライン・契約上の要求・社内ルールを区分し、根拠URL、条項、施行日、確認日、監修担当者、テストケースをルールごとに管理する。資料の更新日だけで全工事に最新版を遡及適用しない。

今回、[2026年7月の経審変更](https://www.ktr.mlit.go.jp/kensan/kensan00000018.html)、[10月の監督処分基準改正等の公表](https://www.hkd.mlit.go.jp/ky/jg/kensan/ud49g7000000e3sq.html)も確認した。これらの詳細な業務ルールは未実装。運搬・物流、新築住宅、外国人雇用等の対象事業も追加調査範囲に含める。

今後の施行として[2026年11月1日の建築基準法施行令改正](https://www.mlit.go.jp/report/press/house05_hh_001149.html)、[2027年4月1日の建築士法の契約関係改正](https://www.mlit.go.jp/report/press/house05_hh_001153.html)が公表されている。2026年10月22日時点の既施行義務として混ぜない。

実装ルールを更新した場合は影響する記録を再確認対象とする。試作は単一バージョンで一括再確認する保守的な設計。本番は施行日・契約日・行為日による版選択と影響範囲別の再審査が必要。

## 今回できること／できないこと

できること：条件の段階入力、必要な確認の表示、資料を伴う確認記録の保存・履歴閲覧・添付ダウンロード、未記録／未解決／条件変更時の次段階停止。取引別の検査・支払期限比較、一部支払、遅延・訂正履歴、ホームの期限警告。既存工事も確認済み扱いには移行しない。写真撮影・記録・請求書作成は停止しない。

できないこと：添付資料の真正性や記載内容の自動審査、資格照会、実在する確認者の認証、会社間共有、期限の自動通知、実際の着工防止、保存期間の保証、複数端末での同時編集制御。開始日と同日の契約交付は時刻を判定していない。既存の受発注・契約・労災画面のサンプル記録も本確認との連動はない。

試作のブロックは法令がすべての工事に同じ資料アップロードを義務付けるという意味ではなく、確認漏れを減らすサービス側の運用要件。一般的な確認欄に資料を付けるだけで法令対応が完結するものではない。

## 本番提供までの必須順序

1. 対象範囲の確定：初期提供する工種、地域、元請／下請、公共工事の有無、対象外業務を明示。未対応業務には対応済み表示を出さない。
2. 建設業法の契約・変更・支払・許可ルールを弁護士等とレビュー。労務は社労士等、設計施工は建築士等、それぞれの専門分野で確認。行政手続の見解が必要な事項は所管庁へ照会する。
3. 会社／利用者の認証、役割別権限、承認者の分離、サーバーでの同じ検証、原本の保管・改変履歴・バックアップを実装。ブラウザを編集すれば回避できる検証を本番の統制にしない。
4. 許可・契約・人員・支払の構造化データを連動し、期限・失効・条件変更を継続監視。緊急工事や過去の未整備発覚には、事後記録と是正の専用経路を用意する。日付の遡及偽装で解決しない。
5. 実際の担当者による操作試験と、該当・非該当・不明・例外・境界値・改正前後の試験を実施。監修者が受入結果と残る対象外を承認してから本番提供する。

今回は調査・確認記録の基盤と、検査・下請支払の一部期限管理まで。全法令対応済みという販売表現や、実務上の着工許可としての利用は不可。
