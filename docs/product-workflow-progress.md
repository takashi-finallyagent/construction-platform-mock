# 契約から施工・請求までの製品実装

更新: 2026-10-26。対象は民間修繕・改修、所属会社の内部利用者。設計: [product-workflow-design.md](product-workflow-design.md)。

## 実装範囲

工事詳細の「工事を進める」に次の5段階を置く。分類の最後から直接移動でき、過去の作業も参照できる。

1. 確認記録: 現行の工事・分類に対する確認事項、日付、結論、理由、証拠資料を追記。許可や資格の内容をシステムが審査した意味にはしない。
2. 見積・契約: 費目別明細、正確な金額・税額、見積発行、契約書案の18入力条件、変更契約、実際に行った交付・承諾等の手動記録。変更契約は当初契約を参照し続ける。
3. 工程・写真: 工事ごとの日程・担当会社・進行状態、工程表PDF、その場の撮影と連続撮影、説明・区分、原本ダウンロード、現場の労災保険の手配記録。
4. 成果・掲示: 施工前・施工中・完成の写真台帳、工事・変更・延期・中止・完了の周知文、発行時点の固定、PDF。
5. 請求・支払: 契約から見積明細を参照する売掛・買掛請求、契約期日、証拠を伴う入出金、追記による取消、完成通知・検査・引渡申出・引渡し・上位入金の実績。

契約の新規確定は現在の民間修繕・改修の分類と資料確認記録を必要とする。分類が古い場合でも工程・撮影・既存債権の請求・実際の支払記録は残せる。確認未了の状態を隠すための遡及修正は行わない。

## 保存と整合性

- 005で `job_workflows`、`workflow_audit_events`、`job_files` を追加。既存の工事・分類・履歴を保持し、架空の業務記録は作らない。
- 006で新規入出金・取消の根拠資料を必須化。証拠がなかった過去記録は書き換えず、過去記録を含む他の更新も保存できる。
- 業務記録は独立した版。更新には業務記録・工事・分類の版一致を必要とする。409や保存結果不明では入力を保持し、利用者が現在の記録と比較して再開する。
- 発行済みの見積・契約書案・請求・台帳・周知文は変更・削除不可。確認・契約交換・入出金・完成等は追記専用。DBトリガーが操作者、サーバー時刻、工事スナップショット、写真台帳のスナップショット、変更前後の監査を強制する。
- 各記録の操作者・サーバー記録時刻は、当該IDが初めて現れた監査版から追跡できる。業務記録全体の最終更新者をすべての記録者として表示しない。
- 数量は小数2桁、単価は整数円。明細の円未満は切捨て。税額は帳票単位・単一税率で1回丸める。混在税率の請求は分けて作成する。
- ファイルは `FILE_STORAGE_DIR`（既定 `.runtime/private-files`）へサーバー生成キーで保存し、DBに元名称・種類・サイズ・SHA-256・所属を記録。認証・会社/工事権限を検証して配信する。UUIDやファイル名だけでは取得できない。
- 画像はJPEG/PNG/WebPの静止画、12 MiB・20メガピクセル以下。ヘッダーだけでなく全画素を復号して検証。PDFは証拠資料として添付でき、ダウンロード配信する。SVGは受け付けない。
- ファイル保存後にDBが失敗した場合、非公開の孤立ファイルが残ることがある。不確実なCOMMIT後に正当なファイルを削除しないための扱い。自動回収は未実装。

## 写真の保存状態

撮影ID・ファイルID・利用者・会社・工事を撮影時点で固定する。端末保管の完了を待って「端末に保管・送信待ち」、ファイルと写真情報のサーバー確定後に「サーバーに保存済み」と表示する。

通信失敗後は同じIDで再送する。写真の追記APIは他の写真や入力を上書きしない。同一ID・同一内容は再送しても重複しない。別利用者・別会社の待機写真を現在の工事へ振り替えない。

端末保管に失敗した写真は画面上で保持し、未保管と明示して原本保存・再送を選べる。ブラウザ終了まで保持できる保証はない。HEIC等は原本を保持し、対応ブラウザで利用者の選択によるJPEG変換を試みる。変換後の画像を原本と呼ばない。

オフラインで画面そのものを初回起動する機能・オフライン認証は未実装。オンラインで開いた現場画面の撮影待ちを保管する方式。実機のiPhone/Android、ブラウザによる保存領域消去、端末再起動時の受入試験は別途必要。

- 既存サーバー・アカウント発行・分類・表示分岐・旧版計算: 102件通過。
- 製品フロントのビルドとサーバー型検査は通過。
- `tests/workflow-smoke.mjs`: 実Chrome・API・開発DBの11項目通過。資料確認→見積→契約案→手動交付→連続2回の変更→工程・撮影→台帳・掲示→請求→分割入金・取消→完成通知→409比較→再読込・閲覧者を確認。工事分類と契約条項の試験入力は一部APIで準備し、帳票発行と事実記録は画面を操作する。

- 工事台帳の既存ブラウザ回帰試験18項目・60画面も通過。
- 分類画面の既存ブラウザ回帰試験12項目・40画面も通過。一度ログイン制限で中断した後、制限を変更せず時間をおいて再実行した。

試験結果はローカルの `outputs/workflow-qa-2026-10-26/results.json`、画面と帳票は同ディレクトリ。ランダムの試験会社・利用者・ファイルは削除し、既存業務データとログイン制限は変更しない。出力とバックアップはGit対象外。

## 本番までの残条件

VPS配備、HTTPS、運用監視、DBとファイルを対にしたバックアップ・別環境への復元、容量上限と保存期間、アカウント招待・再設定・MFA、外部協力業者の工事単位権限、ダウンロード監査、法定期限算定の製品移行、専門家による法令・契約様式の確認が未了。

生成PDFは日本語Canvas画像を埋め込む方式で、文字検索・テキスト選択・アクセシブルPDFには対応しない。PDFバイト列の固定保管・電子署名・外部改ざん証明は提供しない。発行は社内文書の内容固定であり、相手への交付・承諾・契約成立を自動的に証明しない。

外部業務システム連携と専用機器は今回の対象外。届出や資格確認が不要になるという意味ではない。法令適合や本番公開可の宣言は行わない。
